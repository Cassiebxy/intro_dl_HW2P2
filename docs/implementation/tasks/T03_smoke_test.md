## Why not a reduced-class smoke

The starter asserts `cls_train_dataset.classes == cls_val_dataset.classes` and the validation/test label space is the full 8,631 classes. A reduced `num_classes` head (e.g. 200) cannot compute CE against full dev labels, so the smoke path would break exactly where it matters. **Keep the full 8,631-class output space and shrink the workload instead**: limit the number of batches / samples / optimizer steps, not the label space.

## Steps (full chain, 8,631-class output, limited steps)

1. Config: `num_classes=8631` (unchanged); cap work with a small `max_batches`/`steps` per epoch and `epochs: 1–2`. batch_size 64.
2. Train a few steps: loss decreases, no NaN; gradients finite.
3. Save a checkpoint (model + optimizer + scheduler + epoch + metrics).
4. **Restart the kernel/session** (fresh process).
5. Reload the checkpoint into a fresh model — **verify reloaded outputs identical** to pre-save outputs on fixed inputs (this is the *state-integrity* check).
6. **Resume training for ≥1 more step/mini-epoch** — verify the loss continues to optimize after reload (this is a *separate* check from step 5: identical-weights ≠ optimizer/scheduler actually continuing).
7. Classification inference on a dev batch → sensible predictions.
8. Verification inference: embeddings → cosine → `valid_epoch_ver` computes EER/AUC/ACC.
9. Generate `submission.csv` via the **DO-NOT-MODIFY** official cell; inspect columns/row count vs `test_pairs.txt` / cls test; no NaN/Inf.
