## Why not a reduced-class smoke

The starter asserts `cls_train_dataset.classes == cls_val_dataset.classes` and the validation/test label space is the full 8,631 classes. A reduced `num_classes` head (e.g. 200) cannot compute CE against full dev labels, so the smoke path would break exactly where it matters. **Keep the full 8,631-class output space and shrink the workload instead**: limit the number of batches / samples / optimizer steps, not the label space.

## Steps (full chain, 8,631-class output, limited steps)

1. Config: `num_classes=8631` (unchanged); cap work with a small `max_batches`/`steps` per epoch and `epochs: 1–2`. batch_size 64.
2. Train a few steps: gradients finite, loss finite; loss trend over the fixed batch sequence is a diagnostic, not a hard gate (stochastic mini-batch loss can legitimately rise).
3. Save a checkpoint: model + optimizer + scheduler + epoch/global-step + metrics + **GradScaler state if AMP is used** (starter cell 83 omits scaler state — our checkpoint must not).
4. **Restart the kernel/session** (fresh process).
5. **Reload integrity**: in **eval mode** (BN/dropout deterministic), on fixed inputs, reloaded outputs must match pre-save outputs within a documented numerical tolerance (exact equality only where dtype/precision guarantees it).
6. **Resume correctness** (separate from step 5; identical weights ≠ continuing optimizer). After reloading and running ≥1 real training step, verify:
   - model/optimizer/scheduler state restored (e.g. momentum buffers non-zero, scheduler LR matches the pre-save step);
   - epoch/global-step counters continue — cell 85 must resume **from the restored counter**, not restart the schedule;
   - loss and gradients finite after the resumed step;
   - parameters actually changed after `optimizer.step()` (pre/post parameter diff);
   - AMP scaler state restored if used.
   - Fixed-batch loss trend: diagnostic only. Mid-epoch policy must be explicit: either saved sampling position/RNG state, or a declared restart-of-epoch — do not claim bitwise uninterrupted-training equivalence.
7. Classification inference on a dev batch → sensible predictions.
8. Verification inference: embeddings → cosine → `valid_epoch_ver` computes EER/AUC/ACC.
9. Generate `submission.csv` via the **DO-NOT-MODIFY** official cell; inspect columns/row count vs `test_pairs.txt` / cls test; no NaN/Inf.
